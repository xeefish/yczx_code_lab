# 首次发布检查清单

本文供仓库维护者使用，普通成员不需要执行。

## 提交前

- [ ] README、目录结构和本地链接检查通过。
- [ ] `uv run ruff check .` 通过。
- [ ] Git 状态中没有 `.env`、数据库、缓存或个人资料。
- [x] 仓库原创内容采用 MIT License，第三方内容另行标注来源与许可证。
- [ ] 确认第一次组会文件是成员可读摘要，而不是主持人私人讲稿。
- [ ] 使用个人 API Key 依次运行前三个真实模型案例，确认接口、模型名、工具调用和最大步数符合预期。
- [ ] 运行真实模型案例后清除终端环境变量，并再次检查 Git 状态和敏感信息。

## 第一次推送后

- [ ] 将 `main` 设为默认分支。
- [ ] 保护 `main`，要求通过 Pull Request 合并。
- [ ] 至少要求一名维护者评审；人数不足时由负责人暂时承担。
- [ ] 禁止强制推送和删除 `main`。
- [ ] 创建 `question`、`task`、`documentation`、`good first issue` 等标签。
- [ ] 邀请成员时遵循最小权限，不批量授予管理员权限。
- [ ] 实际使用一个测试账号或成员账号完成首个 PR。
- [ ] 在真实 PR 中验证分支保护、评审、修改后再次 push、合并和删除分支。
- [ ] 使用正确和错误目录各测试一次“命名规范检查”，确认成功与失败提示清楚。
- [ ] 首次检查成功后，将“检查成员目录命名”设置为 `main` 的必需状态检查。

## 发布给成员前

- [ ] 从干净目录重新克隆一次。
- [ ] 按 `docs/setup/windows.md` 和 `docs/git/quickstart.md` 从头执行。
- [ ] 验证模板复制、分支、push、PR、评审和同步流程。
- [ ] 按 README 中的完整新成员路径操作一次，确认所有本地链接和 Mermaid 图表在 GitHub 正常显示。
- [ ] 公布求助模板、管理员联系方式和下一周任务入口。
